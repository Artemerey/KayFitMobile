## Что просит пользователь (его словами)
«Не хватает фичи: средняя арифметическая потребления калорий в сутки. Выводить на главном экране, где открывается календарь, среднесуточное потребление калорий. И, так как мы знаем дневную активность пользователя (сколько он тратит), вычитать оттуда — получать среднесуточный дефицит относительно нормы за неделю — и показывать примерное количество килограммов, которые он сбросит, если будет дальше придерживаться этой нормы.»

### Расшифровка в продуктовые требования
1. **Среднесуточное потребление** — среднее арифметическое съеденных ккал в день за окно (по умолчанию **последние 7 дней**).
2. **Дневной дефицит** = `TDEE − среднесуточное_потребление` (TDEE = поддерживающие калории, уже учитывают активность пользователя).
3. **Прогноз веса** = `дефицит_в_сутки × 7 / 7700` кг/неделю (≈ **7700 ккал ≈ 1 кг жира**). Показать кг/неделю (и, по желанию, кг/месяц).
4. Если дефицит отрицательный (профицит) — это **набор**, показать со знаком «+» / другим цветом, не прятать.

- **`lib/features/dashboard/providers/dashboard_provider.dart:129`** — `dailyKcalHistoryProvider` →

  Источник: `GET /api/meals/history?limit=500`, группировка по `createdAt`. **Это готовый источник для среднего** — взять последние 7 дат, усреднить. Уже инвалидируется при сохранении/правке еды (календарь на нём живёт).

### Где брать TDEE / норму / активность
- **`lib/shared/models/calculation_result.dart`** — модель `CalculationResult`: `bmr`, **`tdee`**, **`targetCalories`**, `protein/fat/carbs`, `daysToGoal?`, `targetWeight?`.
- **`lib/features/way_to_goal/providers/way_to_goal_provider.dart:34`** — `calculationResultProvider` → `CalculationResult`.
  Сначала `GET /api/calculation/result`; фолбэк — `GET /api/profile` → `POST /api/calculate`; кэш в SharedPreferences (`calculation_result_cache`). **Может быть null/ошибка** — обязательно обработать (нет TDEE → не показывать прогноз, показать только среднее потребление или подсказку «заверши онбординг»).
- Расчёт TDEE (для понимания): Mifflin–St Jeor `bmr = 10·вес + 6.25·рост − 5·возраст + offset`, `TDEE = bmr × activity_coef`; коэффициенты активности (`daily`→1.725, `3-4`→1.55, `1-2`→1.375, иначе 1.2) в `lib/features/onboarding/screens/onboarding_screen.dart:83`. Вес/рост/возраст лежат на бэке (`/api/profile`), НЕ в `user_profile.dart`.

## Формула и крайние случаи (заложить в план)
- `avgIntake = mean(kcal по дням за последние 7 дней)`. **Открытый вопрос для плана:** считать только дни с залогированной едой, или все 7 (пустые дни как 0)? Пустые дни занижают среднее и врут прогноз — рекомендация: **усреднять только по дням с данными**, и требовать **минимум N дней (напр. ≥3)**, иначе показать «недостаточно данных».
- `dailyDeficit = tdee − avgIntake`.
- `kgPerWeek = dailyDeficit × 7 / 7700`. Округление до 0.1 кг. Знак: дефицит → «похудеет», профицит → «наберёт».
- Нет `CalculationResult` (онбординг не пройден / ошибка) → прогноз скрыть, показать только среднее потребление (или CTA «рассчитать норму» → `/way-to-goal`/онбординг).
- 0 залогированных дней → плейсхолдер, не делить на ноль.
- Числовой шрифт — `K2Fonts.mono` (как в остальных метриках).
